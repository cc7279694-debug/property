## 执行顺序与依赖解释

阅读版明确推荐按编号串行。本仓库采用保守的串行闸门：M01 以前先补齐资料、独立验收 M00、取得用户授权；M02～M23 以前先独立验收紧前模块，再获本模块授权。此闸门用于防止跳模块，不新增产品功能，也不声称是原 ZIP 已列出的精确依赖。

表中“主要依赖”仅列从阅读版能直接辨认的领域基础。后续执行还必须读原模块计划、适用规格和实际代码；来源缺失时不能仅凭本表开始工程。

## 阶段门槛

| 门槛 | 原规划节点 | 所需结果 |
|---|---|---|
| G0 | M05 | 领域、存储和骨架可验证，主要用合成数据 |
| G1 | M13 | 两条业务闭环、完整备份恢复、首页及稳定应用身份/签名；允许长期真实数据 |
| G2 | M19 | 类别、搜索、历史、替换、曲线和年度回顾 |
| G3 | M21 | 两种通知的授权、去重、过期、重建验证；不承诺省电下准点 |
| G4 | M23 | 升级、旧格式、故障、小屏、长历史、签名交付与独立验收 |

以上全部是计划门槛，当前均未执行。M06/M09 Debug 演示不等于 G1 可长期使用。
