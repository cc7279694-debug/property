# M00 — 新项目初始化与规划冻结：任务契约

来源：2026-10-11当前用户M00初始化及补齐工作单。此文件记录当前执行范围；[原M00计划](original-v1/lithic_v1_plan/docs/superpowers/plans/2026-10-10-m00.md)单独保留，不覆盖本文件。

## Goal

在新的 property 仓库接入已提供规划，建立后续会话可恢复的项目记忆，固定产品与工程边界，列出规格问题并交付文档供独立验收。

## Scope

- 文档入口、产品身份、协作规范、当前状态、决策规范、路线与问题清单。
- 原始阅读版保留和校验；记录配套原件是否实际可用。
- 原ZIP安全/完整性核查与原字节归档，接入40份Markdown、3份JSON、24计划、130原案例；保持目录引用。
- 对照原包登记M00～M23编号、精确依赖、边界、门槛与版本演进；区分串行授权闸门。
- 登记Q02～Q06澄清建议/原案例映射/补充测试要求，所有业务测试仍NOT_RUN，建议不自动成为已接受规则。
- 检查文档一致性、链接、敏感信息、Git 差异；建立本地 Git、独立分支，按用户授权提交与推送文档。

## Out of Scope

WHOCARE 的任何改动；M01；Android 工程初始化；UI、数据库、Migration、Repository、功能代码；工具链安装；APK；服务器、Supabase、Vercel、云同步；main 合并、PR 自动合并或产品发布。

## Constraints

- 不改变已确认产品定义；原生 Kotlin/Compose/Room 路线保持。
- 原规划缺失不臆造；问题只能报告和建议，不能擅自改核心规则。
- 一个当前状态文件，沿用 HR-Codex Project Memory System 文档职责。
- 规划、执行验证、独立验收三者分开。M00 文档检查不证明产品功能通过。

## Dependencies

已取得阅读版、完整原ZIP、当前工作单/协作规范、现有功能分支；来源见[规划登记](README.md)。Q01关闭，但完整冻结仍需要独立验收，Q02～Q06状态见问题清单。

## Acceptance Criteria

以 [M00 验收登记](../ACCEPTANCE_MATRIX.md)为逐项结果来源：清晰入口、稳定身份、可恢复状态、顺序和停止边界、问题清单、原文完整性、文档质量、严格范围与 Git 证据。

原件接入已取得实际校验依据；独立验收未满足前不能标记ACCEPTED/FROZEN。当前文档交付可进入评审，带未决规格和后续工程闸门。

## Verification

实际检查ZIP安全/CRC、原文件SHA-256及Git字节、全部Markdown链接、24模块编号/顺序/依赖、130案例JSON/矩阵/计划表一致性和NOT_RUN、原M00三项文档案例、范围/状态、敏感信息、Git差异；提交后核对远程SHA。不存在工程，业务单元测试、Android Build、APK真机验证均NOT_RUN（不适用M00）。

## Stop

本轮补齐交付后立即停止，等待重新独立验收M00，用户再明确授权M01。
