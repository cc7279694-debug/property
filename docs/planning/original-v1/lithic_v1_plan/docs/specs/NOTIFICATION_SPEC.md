# 续费与里程碑提醒规格

## N01｜边界
只有两个开关：续费提醒、里程碑提醒。偏好默认开，系统通知权限是否授予另外展示；Android运行时权限不能由App默认替用户授予。[S6]
不申请精确闹钟、不做常驻前台服务、不要求忽略电池优化才能使用核心功能。

## N02｜续费
候选时间为当前有效付费记录reminderDueOn减3个业务日，业务时区上午9点之后择机执行。
WorkManager负责非精确持久调度与约每日复查，启动/付款修改/状态修改/恢复备份后重新协调候选；不通过执行任务来认定是否付费。
执行前重读数据库，校验服务仍需提醒、周期未被续费替换、未停止以及权限/开关。
已提前录入相邻续费记录的旧到期边界不提醒“该续费了”。推送文案说“记录中的到期日”，不承诺服务商扣款。
错过目标日但仍未到期时最多补一次，按真实剩余天数重写文案；已过期不补发“3天后到期”。无“即将续费”专区和日历。

## N03｜里程碑
长期项目使用真实日期；订阅使用已过去付费有效日期，不能使用已购折算天数。阈值见DOMAIN_CONTRACT C12。
老项目首次录入与备份恢复只建立截止水位，不追发过去节点。用户后改开始日期导致历史跨过阈值，也不补发。
同日多个里程碑合并为一条摘要，打开后到相关详情；不是新增通知中心或成就系统。
目标日错过最多在7日窗口内补一条，超出窗口只保留详情事实，不轰炸历史通知。

## N04｜幂等与系统边界
logicalKey = 类型 + 对象ID + 续费有效期边界或里程碑阈值。确定性notificationId更新同一系统通知；NotificationReceipt唯一键与本地协调锁避免并发重复。
先发布再记回执，进程在中间终止可能重试；使用稳定ID与onlyAlertOnce尽力避免重复响铃。不能宣称对所有崩溃窗口和OEM实现做到严格exactly-once。
相同去重ID恢复后不能变为全新通知；删除项目清除未来任务，过去水位随项目删除，不留孤立引用。
拒绝权限、强制停止、省电、重启和厂商限制会影响送达；WorkManager具体执行时间由系统约束和优化决定，不能写“长期不打开仍准点保证提醒”。[S10]

## N05｜恢复与升级
通知调度是可重建状态。恢复时重建未来候选，不复制WorkManager系统数据库；更新App后检查未来任务不重复。
强制停止后再次打开重算当前事实；已经到期的服务立刻排除总成本，不依赖曾经有没有执行提醒。
