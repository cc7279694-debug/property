# V1 产品规格

状态：用户确认的范围整理；细节按 DOMAIN_CONTRACT.md 补齐。规划不是功能已实现的证明。

## 1. 产品目的
核心目的只有两个：长期回看具体项目的陪伴时间和成本；查看当前已录入项目的日均成本构成。
不把低日均成本称为“更值得”，不把持有时间当实际使用频率，不把成本下降称为一定节省了钱。

## 2. 长期项目
实物、数字买断、永久会员统一放入长期项目。不限定类别或金额门槛，不判断取得来源。
名称、准确开始拥有日期、初始已投入金额为基础输入；一个类别、一张可选封面、一段可选备注。
不记录品牌/型号字段、购买原因、来源、发票、保修、序列号或照片日志。

后续投入和收回逐笔记录日期、金额、说明，不增加“维修/配件/升级”的用户分类表单。默认只纳入取得、维修、升级、配件等长期投入，不纳入油费、电费、停车、话费等日常消耗。
分期按每笔实际支付增加投入，包括已付利息和手续费。时间从开始拥有日期算；不做未付余额、还款计划或催款。
日均成本 = 截至观察日净投入 / 持有天数。闲置不暂停计时。不估二手价。
结束记录日期和原因；真实收回减少净投入，允许负成本。结束后不再进入当前总成本，但数据可修正、遗漏付款可补齐。
允许可选替换关系和历代对比。没有关系的不自动推断。

## 3. 固定周期订阅
只支持月付/季付/年付。固定周期不等于人民币扣款必须永远相同：调价、优惠或实际人民币结算变化允许逐笔输入；不纳入按量 API 等不定周期服务。
每次真实续费由用户确认，保存实际人民币金额、付款日期、周期、本期生效日和真实到期边界。不得到期自动造付款。
允许同一服务改价、改周期、暂停、恢复和停止。保留全部续费记录与停止原因。
月30、季90、年365用于当前标准日均价格和历史折算平均；真实日期用于状态、到期与实际已过去时长，不能互相替代。
免费期不生成付费周期、不计入本产品付费时长。订阅的标准折算时长必须明确标注“折算”，不能称为实际已使用。
暂停仍保留在订阅管理中，独立小分组；停止进入历史。过期而未记录续费的项目显示到期状态，不继续计入首页。

## 4. 信息架构
底部三个主入口：现在 / 回看 / 设置。
现在：首页日均总成本优先，长期项目与订阅分开汇总，下面分别列类别构成；轻量新增入口。累计投入不放首页。
从首页进入长期项目列表和订阅列表。长期项目默认陪伴最久；订阅默认最近实际续费。
回看：长期复盘、历史档案、趋势、类别和年度回顾。不再为每项分析增加一个底部入口。
历史仅已结束/已停止；长期复盘可同时包含当前与历史。两种产品类型分开排行，当前/截至目前最终结果明确标注。

## 5. 类别与查找
长期项目和订阅各有默认类别，支持新增、改名、合并。每条记录恰好一个类别；两套类别不得跨类型合并。
全局按名称搜索当前与历史，不扩展为备注全文、金额、账单搜索。
类别分析保留当前日均成本、投入/收回/净投入、具体项目、年度趋势和替换链入口；不做平均寿命和拥有数量目标。

## 6. 图表与年度回顾
长期项目有日均成本历史曲线，并标投入/收回节点。
订阅有标准日均价格阶梯图，不把调价画成渐变过程。
总日均成本历史默认一条总线，可拆成长期项目和订阅，标关键事件。
年度金额按真实事件日期归属。长期项目投入、收回、净投入分列；订阅另列实际付款。
年度回顾按当前已修正记录动态生成；不保存主观年度感想，不生成消费建议。

## 7. 提醒
续费：真实到期前3天一次；默认开，可统一关闭。不做即将续费专区和日历。
里程碑：100天、1年、1000天、3年、5年、10年；默认开，可统一关闭。不能预付一年当天就宣布陪伴一年。
用户拒绝系统通知权限不影响其他功能，不保证厂商省电环境下准点送达。

## 8. 数据与退出
全部业务记录本地保存。手动完整备份，不加密、不定时、不提醒备份。不做 CSV/Excel 出口。
备份包含所有业务、图片、类别、替换关系、设置和必要的通知去重信息。
恢复完整覆盖，不合并；校验失败或中途异常不能先毁掉旧数据。
真实删除有二次确认，没有回收站。删除会影响后续统计及历史曲线，提示必须说清楚。

## 9. 明确排除
账号、服务器、Supabase/Vercel、云同步、自动银行扣款识别、传统记账、股票、基金、量化、AI、二手估值、预测、目标和预算、评分、推荐买/换/卖、平均使用寿命、每日实际使用次数、自动备份、加密备份、表格导出、发票保修、日记、相册、完整订阅日历。
这些不是“有空再补”的待办，除非用户重新改变产品方向，否则不进入 V1。
