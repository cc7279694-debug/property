# 关键计算、日期和状态契约

这份文件补上先前问答中尚未足够严谨的计算定义。用户选择不改；以下明确标为工程解释的条款用于防止实现者自行猜测。

## C01｜指标语义
首页名称：**当前日均成本**。说明：**仅含已录入且当前有效的项目，按本应用口径计算；不是今天实际扣款。**
长期项目部分是历史净投入除以已持有时间；订阅部分是当前套餐按30/90/365标准天数折算。二者相加是用户指定的参考指标，不是会计折旧、真实生活总支出或资产价值。

## C02｜人民币与精度
金额以人民币“分”的有符号 Long 保存，输入采用金额绝对值加投入/收回方向；初始0元允许。单条绝对值最多999,999,999,999分，输入超过两位小数或非数字直接拒绝，不悄悄截断。聚合使用溢出检查。
计算采用 BigDecimal（DECIMAL128）；展示才按 HALF_UP 四舍五入到两位小数，排序和求和不可用展示字符串。若非零且绝对值小于0.01元/天，显示“<¥0.01/天”或“−<¥0.01/天”，不伪装成0。
总额从未舍入结果聚合。单项各自保留两位小数时允许相加出现分位差，明示“分项四舍五入”；不能为了视觉凑数修改账本。类别数学汇总必须等于对应类型的未舍入汇总。

## C03｜日期
业务日期用 LocalDate / epochDay，写入时间用 Instant，二者不混用。首次启动把设备时区保存为记录时区；后来旅游或系统时区变化不自动改写历史。
所有“今天”经注入的 BusinessClock 提供；测试使用固定时钟。没有 GPS 权限需求。
项目已持有天数 = DAYS.between(startedOn, min(asOf, endedOn)) + 1；开始当天算1天，同日结束也是1天。asOf早于开始时，该项目尚未开始，不计算日均成本；拒绝结束早于开始。
当前项目 ACTIVE/ENDED由结束字段决定。日级历史总成本取日末状态：结束日期当日已从当前合计移除；最终持有天数仍包含那一天。该边界须全应用一致。
金额记录日期必须不晚于记录时区的今天；不记录预测付款。准确的预付款可早于拥有日，结束后的尾款或退款也允许，均保留真实日期。

## C04｜项目计算
投入合计只包含 occurredOn <= asOf 的事件，收回同理。即使今天补录2027年的事件，2027年以后的历史要按发生日重算，而不是按录入日。
使用中：net(asOf) / heldDays(asOf)。
已结束：net(asOf) / heldDays(endedOn)。分母不再增加，分子仍可能因真实后续结算而改变。
结束后收到尾款、退款或继续付分期，不把项目重新变成ACTIVE，也不进入当前总成本；只改历史净投入、当前可知的最终结果和资金发生年份。
详情标“已结束；结果截至今天”，存在结束后金额事件时标“含结束后结算”。图中可把结束后的日均结算值作为历史终值调整展示，不把它当继续使用。

## C05｜资金事件与重复计算
初始投入也是一条金额事件。主表不能同时保存一份可独立编辑的购买价并再次加总。
单次逻辑提交带 commandId（UUID），连点/重试复用同一ID。单行事件使用该操作键；以旧换新等多行操作按commandId+角色派生不同的operationId与实体ID，分别唯一，同组整体重试不能重复付款，也不能把同一唯一键塞进三行。
编辑原记录用于纠错；真实退款是独立收回事件。不能把编辑金额与退款事件同时使用来减同一笔成本。
结束对话框的卖出回收必须写成唯一关联的收回事件；修改金额更新该事件，不能每次保存都新增。
配件独立建项目与记在主项目下二选一；产品不自动识别重复，新增说明提示避免重复记入。

## C06｜以旧换新：明确的非现金例外
用户已选择：旧项目收回3000，新项目取得成本8000（实付5000+折抵3000）。这不是8000元全部现金支出。
实现时旧项目记录 TRADE_IN_CREDIT 收回3000；新项目现金投入5000 + TRADE_IN_CREDIT 投入3000，交易组ID相同。同一数据库事务保存旧项目结束、新项目及3笔金额事件和可选替换关系。
该标记是内部统计语义，不扩展普通投入类型分类功能。年度“投入/收回”包含折抵时显示“含非现金折抵”；不能称为银行卡实际现金流水。
以旧换新默认完整取得当次结算，不支持同时叠加未付分期的组合向导；复杂组合可分笔记录已发生事实，不能把未付款自动补齐。

## C07｜固定周期
BillingCycle仅 MONTHLY(30)、QUARTERLY(90)、YEARLY(365)。每次续费保存该次standardDays，不靠未来可变设置推断旧记录。
固定是周期固定，不是每笔人民币金额完全相同。价格上涨、优惠、人民币结算差异和改月/季/年付均允许；按量API等不定周期账单不纳入。

## C08｜一笔续费的四个时间事实
paidOn：真实付款日。effectiveFrom：本期生效日。paidUntilExclusive：付费覆盖结束边界。reminderDueOn：用户确认的真实续费/到期日，默认等于付费结束边界。
付费区间为[effectiveFrom, paidUntilExclusive)，到期边界当天不属于上一期；表单应明确解释，不靠用户猜包含关系。
免费赠送导致真实到期晚于付费覆盖结束时，只有在用户掌握准确付费边界时才分别录入；免费区间不加入统计。V1不建立免费会员管理模块。
付款可以早于生效日，不能晚于今天；生效和到期可以在未来。没有实际付款就没有续费记录。续费amountCents必须大于0；0元免费期不建付费记录。

## C09｜订阅三个不同指标
1. 当前标准日均价：今天有效且未被暂停/停止截断的付费周期金额 / 该周期标准天数。
2. 折算付费时长：截至观察日已真实付款的续费记录的standardDays之和。这是已购周期折算，包含已付但尚未用完的周期。
3. 历史平均日成本：截至观察日真实续费金额合计 / 折算付费时长。没有付费周期时显示“暂无付费记录”，不除零。
例如年付3650元，付款当天折算付费时长365天、历史平均10元/天；不能显示“已经陪伴365天”。
实际已过去的付费有效天数另外通过付费区间与状态区间交集、截至今天的日期并集计算，仅用于里程碑和必要说明，不替代用户选择的标准折算分母。
首页、历史平均和实际经过时间允许不同，区别写在计算说明；这是不同问题，不是隐藏误差。

## C10｜订阅状态
身份只有一条，用户操作状态使用 ENABLED / PAUSED / STOPPED；有效展示状态 ACTIVE / PAUSED / EXPIRED / STOPPED 由操作状态与覆盖日期共同派生。
ACTIVE：有当前付费覆盖且未暂停/停止。EXPIRED：启用但今天无有效付费周期，不计当前成本，不伪造续费。
暂停不进入历史、不改已付金额/已购折算天数；只停止对应有效区间的当前贡献和实际经过时长。恢复有既存有效付费覆盖时不新增付款；没有则由用户确认真实新付款。
取消自动续费不等于已停止享受服务，App也不能替用户在服务商侧取消。默认停止生效日为已付期结束，仍在付费期内继续计当前日均价；用户明确提前结束时才提前截断。未来生效的停止是用户设置的边界，不是已发生付款。
状态时间线按日期描述，不做小时级使用管理；同一服务同一天只保留一个可修正的日末状态界限，不累计暂停/恢复次数作为指标。过期无须依赖后台任务改数据库；读数据时即可按BusinessClock得出正确状态。没有通知权限也不能影响它。

## C11｜连续、预付、重叠
提前付下一期：年度金额在paidOn入账，但当前价直到effectiveFrom才切换。当前不取“最后一笔付款价格”。
同一服务付费有效区间默认不允许重叠；允许相邻和间断。重复周期或相交周期需要先纠正日期；不要自动叠加两份当前成本。
改周期在新有效期生效，同一服务继续累计历史。V1不自动计算期中升级补差、按天退款、双套餐并存；真实复杂结算必须先形成准确不重叠的记录，不由App猜。
金额记录可以纠错、删除；订阅退款属于当前未确认的产品扩展，V1不做自动退款/比例退时长规则，不能用负续费记录悄悄实现。

## C12｜里程碑
长期项目按真实已持有自然时间；年节点用开始日期加N个日历年（闰日按LocalDate行为落实测试），日节点100/1000。
订阅只按实际已过去的有效付费天数，阈值100/365/1000/1095/1825/3650天；文案采用“累计付费有效天数”，不能把标准已购时长伪装成已使用时间。
初次录入旧数据、导入备份和编辑历史不补发早已过去的里程碑。未来新跨越的节点再发。

## C13｜历史重建
观察日是业务日，不是数据库createdAt。ProjectCostEngine、SubscriptionCostEngine接受asOf；总成本是这两个引擎当日有效贡献的和。
项目关闭后退出总线；订阅到期/暂停/停止区间为0，未付款的空白不得连接成持续订阅。分类统计使用当前类别映射回看全部历史；不额外维护分类归属版本历史。修改分类会重分类历年金额，界面说明“按当前分类”。
删除是真删除，删除后过去图表和年度回顾会重算；不宣称年度报告不可变。
同一天多个事件按日末合计，事件列表全部列出；不虚构小时级先后因果。跨多事件的单个跳变文案为“该日相关事件”，不是“这一笔唯一导致”。

## C14｜年度金额与排行榜
年度长期项目投入/收回/净投入分别按occurredOn统计；订阅按paidOn统计，不把一年预付款按月伪造拆分。两类年度金额不强制合为一个总支出。
长期项目当前/结束混合排行但标状态与口径；零成本和负成本不剔除，不能用“最值得”标题。订阅另榜，时间按“折算付费时长”标示。
替换链每个项目最多一个前任、一个后任，禁止自指与环；建立关系不自动结束旧项目。删除中间项时解除相邻关系，不擅自重连推断。
