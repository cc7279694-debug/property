# 页面与交互规格

## U01｜结构
底部固定三个入口：**现在｜回看｜设置**。搜索为顶部轻入口，新增为不压过成本主数字的加号。

现在 → 长期项目列表 / 订阅服务列表 → 详情 → 编辑/投入/续费/结束等操作。
回看 → 长期成果 / 历史档案 / 成本趋势 / 类别分析 / 年度回顾。
设置 → 完整备份与恢复 / 两种提醒开关 / 计算说明 / 关于。
不把全部统计直接塞在首页，不为每项图表造一个底部Tab。

## U02｜首页
唯一主视觉为当前日均成本。第二层分别列长期项目与订阅小计、各自类别贡献。累计投入、年度总结、榜单和最近活动不挤占首页。
没有数据时显示“暂无记录”和轻量新增，不造演示记录、不画假趋势；真正有零成本项目时才显示¥0.00。
过期订阅不纳入；提前付未来周期不提前增加当前价格；结束项目退出。点类别进入对应列表/分析。

## U03｜基础视觉
首版一套跟随系统的明暗外观，不做主题商店或多套装饰主题。基调以低饱和中性色为主，金额、持有时间和状态具有稳定层级；涨跌不用红绿暗示好坏。
主数字建议36–40sp，页面标题24sp，正文16sp，辅助13–14sp；4/8/12/16/24/32dp间距。触控区域至少48dp，图表必须有文字替代内容。360dp窄屏和字体放大到200%验收。
生产列表卡片统一：封面/占位 → 名称 → 当前/结束状态 → 时间指标 → 日均成本。两类项目的标签不同，不能通用一段错误文案。

## U04｜长期项目表单
必填：名称、准确开始拥有日期、初始实际投入；类别默认该类型“其他”，图片/备注可选。
初始投入付款日默认开始拥有日，实际预付/分期时间不同可展开修改；只填0也允许，不虚构全价。
后续输入：投入或收回、金额、日期、说明。用户不用选择维修/配件等细分类。
保存有忙碌态与重复提交保护；成功后才退出，失败保留输入。离开已修改表单时有放弃确认；不保存一堆自动生成的业务草稿。

## U05｜长期项目详情
顶部：名称、状态、已持有时间、当前/截至目前最终日均成本。
次级：累计投入/收回/净投入，按时间的金额事件、封面、备注、替换关系入口。
结束操作不是删除；明确说明退出当前合计。结束后仍能修正记录、补录真实尾款/退款；不增加实际持有天数。
删除确认明确“将删除项目及金额记录，历史统计也会重算；无法在App内撤回”。

## U06｜订阅表单与续费
新增身份和首次付款尽可能一个流程事务保存。不生成空付款。可用前次价格/周期预填，但预填不是确认、到期不是付款。
续费必须确认金额、付款日、周期、生效日、实际到期日。每月两次扣款等异常要核对覆盖日期，不自动猜。
未来已付周期在完整历史里标“尚未生效”；列表最近续费排序按真实paidOn，不按生效时间伪造排序。

## U07｜订阅详情与状态
顶部保留历史平均日成本和“折算付费时长”；明确说明按30/90/365折算。当前套餐与当前日均价独立区块显示，避免以为同一数字。
“实际已过去的付费有效天数”只作为里程碑/计算说明辅助，不再加一张抢主视觉的卡。
订阅中与暂停分组；未续费且已过期的身份留在服务列表并标“已到期”，不强迫用户处理，不额外做待办工作流。
停止订阅会先解释“这只改变本App记录，不替你在服务商处取消”。默认有效期结束才退出当前成本，明确提前停止才提前截断。

## U08｜回看与榜单
长期项目、订阅各自切换。当前和历史混排时每行展示当前/已结束与相应指标。
长期榜：陪伴时间最长、日均成本最低；标题不叫最值得/性价比评分。订阅时间榜叫折算付费时长，不叫实际陪伴榜。
历史档案单独筛已结束/已停止；不和暂停混淆。
替换链最多一前一后；断链不自动猜。对比页为纵向对照，小屏不强制横向超宽表。

## U09｜图表
单项目成本曲线不预测，投入/收回事件可点；同日多个事件打开同日列表。含负值时Y轴允许负区间。
订阅用阶梯图，非有效期间为0并标暂停/到期，不把前后价格平滑连接。
总趋势默认总线，可展开两类拆分；金额单位统一“元/天”。年级汇总若按年末取点必须叫“年末日均成本”，不能叫“全年平均”。
年度金额是柱/条形与数值，零数据不是错误；无记录年份应显示“未录入相关记录”，不推断该年没有花钱。
20年历史抽样不能丢掉新增项目当天的大峰值，事件点必须可达。图表提供可读数值列表；不是只靠颜色和拖动才能看。

## U10｜范围止损
M05先验证导航、表单、列表、详情和首页的基础层级；M22只做一致性与真实交互打磨，不重新设计一个新产品。
Logo接入必须有实际可用资产文件；不能声称已用早前批准但当前未提供的图。工程期允许明确临时图标，正式发布清单必须标明最终接入情况。
