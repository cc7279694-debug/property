# 完整备份与恢复规格

## B01｜用户体验
设置中仅“导出完整备份”和“恢复完整备份”。完全手动，不加密、不设密码、不做定时备份、不提醒备份、不做CSV。
提示备份为可读内容，应妥善保管；无密码只是降低操作负担，不等于更安全。
选择系统本地文件位置导出；系统文件选择器可能提供云盘，不能把用户主动选云盘描述为App自动同步。[S5]

## B02｜逻辑备份而非直接复制正在写的.db
一个ZIP，建议扩展名`.lithicbackup`，包含manifest.json、data.json、settings.json、media/及各文件校验值。
不把正在运行的SQLite主文件简单复制后声称备份完整；逻辑导出使用同一一致性数据库读取快照，并协调图片/设置写入冻结。
DTO用稳定字符串ID、人民币分、ISO日期和显式枚举；不序列化Android对象、绝对路径、临时URI或Kotlin类名。

manifest包含：formatVersion、minReaderFormat、producerAppVersion、sourceDatabaseSchemaVersion、createdAt、recordZoneId、recordCounts、文件名/字节数/SHA-256。
settings只包含应用偏好和必要水位；不包含系统授予权限、签名密钥、WorkManager内部任务和临时缓存。
哈希校验用于发现损坏，不是加密，不证明文件没有被恶意重写。

## B03｜导出一致性
所有会改业务、封面或设置的用例通过同一个本地写协调器；导出取得短时独占快照锁，读取Room事务快照、复制不可变图片和设置到内部临时区，再释放。
图片以不可变资源ID存储，替换封面生成新资源；导出未完时不能清理被引用资源。
内部文件完整且校验通过后，才写用户选择的目标URI。写入/关闭失败不报告成功，尽力删除不完整目标文件并提示。
内部临时快照不是用户自动备份；操作结束清理，不提供历史备份列表。

## B04｜导入先验证
选文件 → 安全解压到私有临时区 → 格式迁移 → 字段/外键/金额/日期/状态/区间/无环/图片哈希校验 → 展示记录摘要 → 用户确认覆盖 → 激活新数据集。
任何校验失败都不修改当前数据。

拒绝：未知更新格式、缺失必要字段、未知周期、非法金额、重复ID/operationId、孤立外键、重叠付费期、自替换/环、图片缺失或哈希不符、目录穿越和压缩炸弹。
ZIP条目必须解析并验证最终规范路径在临时根内，禁止绝对路径、`..`、反斜杠混淆、重复规范路径、符号链接及未声明文件。Android官方也专门指出ZIP路径穿越风险。[S8]

防护上限：解压总量1GiB、条目10000个、单张已存封面2MiB、单个data.json 128MiB、每份数据记录合计200000条；达到上限明确失败，不截断导入。图片解码先看尺寸，像素总数上限40MP，再转为最长边1600px的受控格式。
缺失图片的旧备份不得静默“完整成功”；用户需要修复源文件或使用明确的故障说明，V1不另做部分导入模式。

## B05｜覆盖恢复不能靠一次Room事务假装覆盖全部文件
Room、图片和DataStore不是同一个事务资源。采用最小的“完整新数据集 + 原子指针切换”方案，不引入分布式事务框架：
```
noBackupFilesDir/
  active-generation      # 小型原子指针
  generations/<uuid>/
    data.db
    media/
    settings.pb
    ready.json
```
新备份先导入到独立generation，数据库校验通过，图片和设置写完关闭并刷新，生成ready标记。
全局恢复锁下停止旧任务写入、关闭旧Room/DataStore作用域，再用AtomicFile切换一个active-generation指针；启动只打开指针指向且验证完成的数据集。
Android的AtomicFile提供单文件原子更新，不会替多文件加锁，因此独占锁、完整新目录和先验证顺序缺一不可。[S9]
若切换前失败，旧指针不变；若切换后进程终止，下次启动按新指针读取完整新数据。新集启动验证失败时使用仍保留的前一完整generation回退，并显示失败，不静默清空。
前一generation在新集成功打开并完成验证后清理。这个短暂安全回退不是回收站、自动备份或合并功能。

## B06｜版本兼容
数据库schema和备份format各自独立编号。导入旧备份先迁移DTO再写当前数据库，不要求用户安装旧APK。
格式v1在M11建立；M16加入以旧换新与替换关系后升v2；M20加入提醒水位后升v3。每次升级必须保存合成的旧格式样本并做往返与迁移测试。
未知更新版本明确拒绝，不能跳过字段“凑合导入”。

## B07｜恢复后的行为
重新计算所有派生数据，不信备份中的缓存/图表结果。
重建未来通知任务，不把旧系统任务搬到新设备。保留已通知逻辑水位并设置导入截止点，不补发过去一串里程碑。
系统通知权限仍由新设备用户决定。恢复出的“提醒偏好开”不代表已获得权限。
恢复成功后的当前日期可能晚于备份日期，项目天数和过期状态按今天算，不要求看起来与导出日数值完全相同。

## B08｜必测故障注入点
选择取消、URI写入失败、空间不足、解压中断、图片损坏、DTO迁移失败、建新库失败、指针切换前崩溃、切换后崩溃、新数据集首次打开失败。
每一点必须证明旧数据完整可读或新数据完整可读，不出现混合代；不能仅证明“没有抛异常”。
