# 决策登记

## 已确认，不再重复提问
U01 纯本地Android APK，新项目，不在WHOCARE上大删改。
U02 长期项目+固定周期订阅；物品与数字买断统一；用户自行输入来源无关。
U03 展示事实，不评分、不预测、不设目标、不代替消费判断。
U04 项目累计净投入/持有天数；闲置不暂停；后续投入逐笔；分期按已付含手续费。
U05 真实退款/卖出减少成本，允许负成本，结束后历史可修正。
U06 可选替换链和历代对比；以旧换新旧收回、新完整取得成本。
U07 订阅真实确认后才记续费；支持暂停/恢复/停止、价格与周期历史。
U08 月30/季90/年365用于当前和历史标准折算；免费与停订不额外计入。
U09 首页总日均成本主角，下面类别构成；累计投入不在首页。
U10 当前列表分两种，项目陪伴最长、订阅最近续费；历史独立，复盘跨当前和历史但类型分开。
U11 类别分体系、一个项目一个类别、可新增改名合并；不做平均使用寿命、数量目标。
U12 单项目/订阅/总成本曲线与事件节点；年度金额按真实发生年，投入收回分开，类型分开。
U13 客观年度回顾，不写主观年度总结。
U14 一张封面、可选备注、名称搜索，无品牌字段、发票保修、相册日记。
U15 两种提醒默认偏好开但可关闭；续费提前3天一次，无续费专区和日历。
U16 手动完整备份含图片设置；不加密、不自动、不提醒；覆盖恢复不合并；真实删除无回收站；无表格导出。

## 本轮补充的默认解释（不是声称用户逐项已选）
D01 主指标是已录入项目的混合日均参考，不叫真实每日生活支出/折旧。
D02 项目自然日含首日和结束日；日末合计在结束日排除。记录时区首次取设备并固定。
D03 金额分与日期集中计算；舍入仅展示，不同页面不可复制公式。
D04 项目计时结束与款项结算分开；允许真实尾款/分期/退款发生在结束后。
D05 以旧换新是非现金折抵例外，标注含折抵，不等于银行卡现金流水。
D06 订阅标准累计天数改称折算付费时长；里程碑只按已实际经过的付费有效日期，不因预付提前解锁。
D07 过期未续不继续贡献；取消自动续费不等于已付期立即失效；当前价格按有效期而非最后付款。
D08 简化不重叠付费周期；同一期自动补差、自动退款、免费管理模块不引入。
D09 分类变化回溯重分类，年度回顾动态重算；不建双时间审计系统。
D10 备份提前，第一版承载真实数据前须通过恢复；逻辑快照、校验后切换，而非先清空。
D11 单app工程按职责分包；24个交付模块不是24个Gradle模块。
D12 固定应用身份/签名、系统备份排除、无网络权限都是发布前必要检查。
D13 先M00–M13形成安全核心，再展开复盘；分析和图表已有独立模块，不因先用核心就永久取消。
D14 通知是尽力送达，不申请精确闹钟；接收权限不可自动恢复。
D15 暂停服务留当前管理区独立分组，不放历史；未知/未来准确付款不伪造。

## 范围变更
任何新增要求记录：原规则→新规则、受影响数据/图表/备份/迁移、验证案例、用户授权。不能把“多规划几个板块”理解为再加AI、云同步或预算。
