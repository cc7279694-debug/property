# 执行规则

1. 开始先读 PROJECT.md、docs/CURRENT_STATE.md、docs/DECISIONS.md、目标模块计划和其引用的规格。当前明确请求仅为规划；没有单模块实施授权时不得写产品代码、创建远端项目或推送。
2. 用户已确认的产品选择优先；本轮补充工程规则列于 DECISIONS.md。不能用旧 WHOCARE 文档覆盖新产品边界，也不能把 Mirra / RECIPIO 的功能混进来。
3. 一次只实施一个模块或明确批准的子任务。按依赖验收基线起步；不得自动串行跑完整路线。
4. 先添加针对行为的失败测试，记录有意义的失败，再做最小实现并回归。环境启动失败不能冒充需求测试的 RED。
5. 公共金额/日期/成本规则集中在领域引擎；页面、图表和数据库查询不得各复制一套公式。
6. 不引入网络客户端、统计 SDK、自动上报、云同步、登录、AI、精确闹钟权限或广泛文件访问权限。
7. 业务库禁止 destructive migration；所有 schema 变更必须带迁移测试、完整备份兼容测试和版本记录。
8. 别把用户数据、图片、备份、签名密钥、密码或真实日志提交 Git。测试仅用明确的合成数据。
9. 每次领域结构变更都必须同步备份 DTO、格式迁移和往返测试。不允许出现“新字段先不备份，以后补”。
10. 只暂存本模块修改；已有不相关工作不动。是否提交/推送遵循该次用户授权；禁止强推、重写主分支、创建付费资源。
11. 完成报告列真实命令、退出码、通过/失败/跳过数、APK 路径与 SHA-256（若确实产出）、schema/格式版本和限制。未运行写 NOT_RUN，不能写 PASS。
12. 实现者完成只到 READY_FOR_REVIEW；独立验收后才可标 ACCEPTED / FROZEN。不能凭自评自动冻结。
13. 每模块完成后停下。不增加“顺手做”的下一模块；不自动决定功能取消。
14. Git 撤回不等于数据库可降级。禁止让旧 APK 打开比它更新的数据库；修复优先前向迁移。
15. 单个 Android app module，按功能分包。只有客观的编译、团队隔离或复用需求证明必要时才另开 Gradle module。
