首页不把两个独立读取冒充跨对象原子快照。只读组合拟按当前repository身份、请求序号和同一业务观察日校验发布，监听既有变更；迟到结果不得覆盖新状态，失败保留上次结果并明确提示。当前LedgerUiStateHolder只有collectLatest取消与直接发布，还没有上述epoch校验；这是阶段1计划而非已实施事实。已录入数量>0而当前管理子集为空时，展示“当前列表没有记录”及历史入口，不声称全部账本为空。

## 5. 页面结构与状态

**现在：**“现在”标题与短说明→真实概要→我的长期项目（最多3）→我的订阅（最多3）→足够底部留白。两类“查看全部”进原路由。全空时小线性图标、一句“从第一条记录开始”、一个新增按钮；成功读到空才显示空。非空时唯一主要新增入口是FAB。新增底部菜单为两行图标/标题/短说明，整行可点，取消不触发业务discard或预写。

**项目列表/详情：**当前/历史同组件不同范围；列表状态、稳定排序和继续加载保留。详情基本信息/真实金额记录/备注及结束信息分组；记录投入主按钮、记录收回次按钮；编辑资料/封面/结束或修正结束/删除归有标签的更多操作，原条件和确认不变。现有未保存或待确认任务仍可返回核对。

**订阅列表/详情：**列表保留订阅中/暂停/到期分组，已停止从回看进入。顶部历史平均+折算付费时长；当前套餐独立；付款记录、状态事实、备注分组可展开且保留原分页。确认续费、暂停/恢复、固定计划停止/提前停止、修正/取消、原身份重开、付款纠错/安全删除保持。已付款但尚未生效的周期、固定停止边界和“仅改变本App记录”说明可见，付款日仍不得晚于业务今天。

**回看/设置：**回看只保留历史档案/已停止订阅两个带说明的入口；不以项目总count断言历史为空。设置为记录与数据/关于分组，只读时区/本地说明/真实版本、紧凑但醒目的开发体验风险；展开长说明，无假备份/提醒/帮助箭头。创建/编辑/付款/纠错/封面等旧表单在阶段2统一组件，字段、raw、初值、校验及提交阶段均不删减。

## 6. 图片展示与资源上限

复用同代MediaRepository.openAsset，UI不再包coordinator锁，不绕过元数据/文件校验。现CoverDisplay已在IO读取，但每张可全解码至1600且无共享并发预算；扩展列表前应只在UI读取/预览层补采样与资源边界，不改媒体安全协议。

拟用同一UI生命周期的预览加载器：并发最多2；decode边界后按列表约128–256物理像素或详情实际需要尺寸采样；应用持有的已解码LRU目标≤8MiB，键含repository/generation归属、assetId、目标尺寸。超缓存预算的单图不入缓存；这不是整个进程/可见ImageBitmap总内存硬上限。只缓存缩略像素，页面重入与资源变更仍调用既有openAsset校验；当前校验失败先移除该身份旧缓存，不能用旧成功图掩盖坏图。换代/关闭/离开取消任务并释放加载器持有引用，不手工回收仍被Compose显示的Bitmap。

禁止无界预取/一次解码全列表、重组反复解码、永久保存content URI、直拼私有路径或再规范化资源。若必须改Repository/协议才能完成，单列问题停步。已确认的JPEG缺陷独立保留；缩略显示成功不构成原始输入完整性验证。
