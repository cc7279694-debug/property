# LITHIC V3 设计系统

V3-02 · 设计候选。数值用于高保真比较和后续 Android 验收，正式产品选择等待独立审查与用户视觉确认。[V3-01 设计策略](../lithic-ui-v3/V3_DESIGN_STRATEGY.md) · [概念对照](CONCEPT_COMPARISON.md) · [画板索引](HIGH_FIDELITY_SCREENS.md)

## 1. 品牌视觉语言

**记录拥有，理解成本。** 砺石是一份安静的个人物品档案。沿用砺石名称和黑石标识。项目以原始封面、名称、持有事实形成识别顺序，订阅以名称、服务类型和当前状态形成识别顺序。可比较的成本随后成组出现。品牌来自对齐、留白、材质和真实记录，首页无需额外标语。

- **档案页面**用连续条目、完整封面和清晰行分隔。首页 A 先看到正在拥有的东西，再读总成本。首页 B 先读总额与两类构成，再看档案。
- **录入页面**用任务标题、字段、后果与提交建立顺序。风险文案与动作相邻。
- **分析页面**用选中日期与准确读数建立焦点，图形帮助理解变化，原始事件可继续查阅。
- **设置页面**依任务分组，标题说明可做的事。备份导出、检查和覆盖恢复各自保留路径和结果。

警告、错误、确认成功按独立语义角色组织。已选、有误、处理失败、数据未核对等均有可读文字。负金额以真实符号与业务标签表达。控件边界和焦点线使用专门高对比角色。全套正常、禁用、焦点、选中和模态叠层的实际对比度需在最终呈现下复测。[对比度抽样与验收](ACCESSIBILITY_AND_RESPONSIVE.md)

## 3. 字体与金额

Android 用系统无衬线及中文回退字体。画板中文使用本机无衬线回退，字形与真实 Android 可能不同。画板的重点数字可放大至 38 CSS px，以比较两种首屏。下表是原生试做的字级候选。金额可用等宽数字对齐。候选字级按职责使用，系统大字体允许块级重排。

| 角色 | 字号 / 行高候选 | 用途 |
| --- | --- | --- |
| 重点读数 | 32 / 40sp，500–600 | 首页总日均、选定日总成本 |
| 记录名与页标题 | 24 / 32sp，500–600 | 详情主体和顶层标题 |
| 分组标题 | 18 / 26sp，600 | 项目、订阅、付款、金额事实 |
| 条目名与输入 | 16 / 24sp，400–600 | 可点击条目、字段、主要动作 |
| 事实与短读数 | 14 / 20sp，400–500 | 真实日期、时长、状态、条目读数 |
| 图表刻度与短注记 | 12 / 16sp，400–500 | 刻度和小型辅助信息，正文另有完整读数 |

金额显示沿用既有口径。项目日均成本、订阅历史平均日成本、订阅当前标准日均价、首页总日均、实际付款各有完整名字。整组表达人民币、正负符号与单位，支持原有完整金额查看与复制。真零显示 ¥0.00，缺值用「—」及其原因。长金额先让布局改行，再按现有完整值交互处理。[现有金额语义](../../../app/src/main/java/com/cooper/lithic/core/design/MoneyMetric.kt)

## 4. 间距

候选刻度为 4、8、12、16、24、32dp。紧凑屏默认左右 16dp，较宽窗口从 24dp 起。画板常规内边距采用 20 CSS px，窄屏和大字采用 16 CSS px，便于评审密度。行内事实间距 4–8dp，封面与名称间距 12dp，条目间可用 12–16dp 内边距，分区靠 24–32dp 留白及细线。触控区至少 48×48dp，视觉图标尺寸独立。

## 5. 图标

沿用现有品牌和明确语义的 Android 图标语言。返回、搜索、更多、添加、信息等使用统一 20–24dp 视觉尺度，单独交互目标保留动作名称。无封面状态使用项目或订阅类型图标，无需重复图标底板。存在独立封面操作时，封面和打开档案分别命名。共用图标不加装饰性朗读。

## 6. 形状

照片框从 8–10dp，按钮、字段从 12dp，主要对话框、底部面板从 20–24dp 比较。规则连续的档案行使用直边或轻边界。圆角有功能含义，明显圆形仅用于原生圆形指示与按压回馈。

## 7. 表面

三层候选为内容画布、任务表面、模态层。档案行和设置项优先共享同一平面。输入、当前选择、重要风险说明在需要区分时用轻色表面。列表、详情、表单、分析和设置按各自任务组织，只有浮层需要独立覆盖层。确认操作期间保留一致背景，正在处理时明确状态与当前可用操作。

## 8. 阴影与分隔线

普通列表、设置分区、静态统计默认平面。分隔线与分区标题、留白一起使用。模态面板和遮罩可用轻阴影及色阶传达层级。图表的零线、选择线、分项线须可辨；弱分隔不承载焦点、选中或危险状态。

## 9. 封面与档案身份

| 部位 | 候选 | 规则 |
| --- | --- | --- |
| 首页和记录清单 | 80×60dp，受限时 64×48dp，4:3 | 照片保持原比例完整 Fit，空白区域取主题中性色 |
| 搜索结果 | 紧凑身份图位，至多 64×48dp | 同名、同封面和同类型图标，靠文本区分项目、订阅和历史 |
| 项目详情 | 4:3 内容区或随可用宽度限制的完整图片 | 图像与名称、类别、状态、时长直接相邻。项目 A 提升其首屏识别权重 |
| 订阅详情 | 类型标识加名称，已有可读封面沿用 | 内容围绕服务和付款，不凭空增加订阅商标或图片 |
| 无图、读取中、不可用 | 复用同一尺寸槽位 | 无图显示类型标识。读取中稳定占位。不可用保留原因和已有反馈 |

画板的紧凑图位用 64×48 CSS px。首页 A 的主要封面及详情使用较宽完整图面，先验证档案主次。画板素材使用合成或有许可的封面，实际生产封面只读既有记录。是否可改、查看、删除引用或参与恢复，继续由现有能力和状态决定。[封面实现](../../../app/src/main/java/com/cooper/lithic/feature/media/CoverPreviews.kt)

## 10. 页面宽度与响应式

候选基准为 360dp 紧凑屏，320dp 先压缩配图和行间距，400dp 给事实适当展宽。两列数字不足时先改成单列，金额和动作保留可达。中等及展开窗口优先限制阅读宽度，列表与详情双栏须在原导航返回、焦点和多窗可用性确认后讨论。表单建议最大 560dp；广宽档案建议从 640–720dp 比较。详见[响应式验证矩阵](ACCESSIBILITY_AND_RESPONSIVE.md)。

## 11. 导航与操作

紧凑窗口保留 Material 三个底栏入口「现在／回看／设置」，选中标签明确。详情、表单和其他次级目的地沿用原来源链。系统 Back、顶栏返回、预测返回及切换主目的地均遵守原有守卫。两个概念的首页新增按钮都占用独立测量区域，排在滚动内容下方及底栏上方，不叠在正文上。首页仅一个新增入口，进入既有类型选择。主按钮正常按压反馈即可，动效服从系统设置。

## 12. 表单与确认

首屏展示任务、对象和必填事实。真实发生日、拥有日、实际付款日、覆盖起止和提醒到期日按业务分组。字段错误在字段附近呈现，保留输入，允许滚动定位到未通过的字段。提交和确认采用测量后的底部操作区，兼顾 IME 和大字。次要操作以文字或次按钮呈现。

- 金额新增区分投入、收回与纠错。原笔纠错对照原事实与新值。初始实付真零可填写，空白仍需校验。
- 订阅续费、暂停、停止与纠错各有目标和后果。停止仅改变本地记录。可用管理入口取决于当前状态。
- 结束持有、永久删除、放弃草稿、覆盖恢复各用准确动词。涉及影响范围时，在确认区显示对象、变更和取消。未保存、提交中、待核对与确知失败保持独立反馈。
- 待核对写入沿用同一提交身份的核对；已确认但重读失败提供只读重查。覆盖恢复需单独核对备份与主动确认，不把完整性检查通过当作恢复结果。

## 13. 图表

读序为指标名称、选定日期与值、图形、分项贡献和相关事实。轴单位明确，线型、点标识和图例共同区分序列，负值与零线可见。当前无贡献、日期缺失、真零和旧数据保留独立表现。保持精确选日、前后日、文字列表、事件和原记录入口。年度显示项目实际投入、收回与净投入，订阅实付独立呈现。图表作为浏览入口，金额事实与回看语义保持一致。[现有图表](../../../app/src/main/java/com/cooper/lithic/core/design/CostChart.kt)

## 14. 无障碍

最小目标 48×48dp。名称、事实、完整读数作为条目顺序，状态可用语言辨认。角色、选中和错误用原生语义，焦点路径以可执行顺序为准。覆盖普通文字 4.5:1、大号文字及关键非文本目标 3:1 的测量计划；系统字号 100%、150%、200%，窄屏、横屏及键盘需原生复查。[验收细则](ACCESSIBILITY_AND_RESPONSIVE.md)

A–K 的生产路径、数据合同和保护以 [V3-01 用户旅程](../lithic-ui-v3/USER_JOURNEYS.md) 为准。V3-02 保留一个正式产品身份，画板用于设计审查。
