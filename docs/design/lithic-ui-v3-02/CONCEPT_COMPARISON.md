# 两种信息架构

设计起点为 [V3-01 现状审查](../lithic-ui-v3/UI_AUDIT.md)。六个对照画面使用同一账本、同一岩白雾蓝主题、相同记录和动作。布局可纵向滚动，静态画板是给定视口的截面。[合成数据](HIGH_FIDELITY_SCREENS.md#合成账本)

## A · Personal Archive 私人物档

| 页面 | 阅读顺序 | 设计理由 |
| --- | --- | --- |
| 现在 | 长期项目 → 阅读器封面、名称及持有事实 → 其余项目 → 当前日均成本 → 订阅 → 含历史数量和构成 | 从熟悉的物品进入账本。把首页总日均收成可识别的行，金额、截止日、非今日扣款与计算说明仍在一起。首条遵从现有项目顺序，照片突出只是排版规则。 |
| 项目详情 | 名称、类别、状态、持有 → 完整封面 → 项目日均 → 累计投入/收回/净投入 → 金额记录 | 项目被识别之后再读成本。在同一条目内解释总额、日均与实际事件的关系。 |
| 订阅详情 | 服务名称、状态和真实付费覆盖 → 当前套餐与标准日均价 → 历史平均日成本及折算付费 → 实际付款 | 先回答“当前买的是什么、什么时候到期”，随后核对跨历史付款的均值。未设置封面的订阅由文字和类型图标标识。 |

## B · Ledger Overview 成本总览

| 页面 | 阅读顺序 | 设计理由 |
| --- | --- | --- |
| 现在 | 总日均与截止日 → 项目/订阅当前贡献 → 构成入口 → 两类明细 → 含历史数量 | 方便经常核对账本成本的人按总额、分项、记录顺序对照。两类贡献共用一个平面和分隔，明细使用均匀清单。 |
| 项目详情 | 项目日均与截至日 → 累计资金 → 名称、缩略封面与持有事实 → 金额记录 | 用户从费用比较进入时可以立即核对值与分母。缩略图与名称保持现有对象身份。 |
| 订阅详情 | 历史平均日成本与折算付费 → 当前套餐与标准日均价 → 服务身份和覆盖 → 付款 | 先支持跨时间和套餐比较。标签逐项区分历史平均、当前标准价与实际发生付款。 |

- [项目详情 · A/B 画板](boards/renders/compare-project.png)
- [订阅详情 · A/B 画板](boards/renders/compare-subscription.png)

A 的代价是总账读数比 B 晚出现，首条无封面、字体放大或名称极长时尤其明显。B 的代价是照片更像标识，且首页先建立指标分组，容易复现现状中的仪表盘阅读习惯。两个方案都保留独立新增区和三目的地导航；详情里的续费、记一笔、菜单与回退仍遵守原资格。

**暂推荐 A 作为全应用延展基准。** 「记录拥有」由档案条目承担，项目、订阅和搜索之间更容易维持同一身份。B 的总量、分项、事件顺序适合回看中的分析页面。A 的首页仍需核对总日均在常规 360dp 的可发现性，以及放大字号时向下浏览到成本的路径。方向和画板等待独立审查及用户确认。
