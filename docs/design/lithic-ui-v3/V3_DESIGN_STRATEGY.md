# LITHIC V3 设计策略

**审查提案 · UI-V3-01**。视觉数值为后续概念稿的起点，交互与业务语义沿用当前正式产品源码。依据见[现状审查](UI_AUDIT.md)、[页面清单](APP_INVENTORY.md)与[用户旅程](USER_JOURNEYS.md)。

## 1. 品牌视觉定位

**砺石是一份安静的个人物品档案。记录拥有，理解成本。** 品牌理念用于设计判断，首页沿用「砺石」与现有黑石图标。打开首页能立即找到成本，继续往下自然读到自己的物品与订阅。进入一件物品时，名称和用户封面确立身份，持有状态与成本解释这条记录，时间线说明这些数字如何形成。物品页由内容塑造气质，工具页由操作效率塑造气质。

借鉴 Apple 的字重节制、对齐、留白与内容优先。使用 Material 3 的按钮、输入、弹窗、底栏和系统反馈，并通过 Compose 颜色、字体与表面角色表达砺石。以实际录入的项目名、可选封面和持有日期构成产品的个性。

## 2. 色彩体系

设定画布、抬高表面、正文、辅助文字、分界、操作、状态与图表角色。操作色仅用于可操作元素、选择和焦点。金额统一使用正文色，负号与状态文字表达业务事实。警告、错误和明确成功各有文字及形态，关键警告与其动作放在同一处。

| 角色候选 | 岩白雾蓝 | 纯白 | 深色黑灰 |
| --- | --- | --- | --- |
| 画布 | `#F7F6F2` | `#FFFFFF` | `#121212` |
| 抬高表面 | `#FFFFFF` | `#F7F7F7` | `#1E1E1E` |
| 正文 | `#29343E` | `#171717` | `#F3F3F3` |
| 辅助正文 | `#4E5D67` | `#5C5C5C` | `#B2B2B2` |
| 操作前景 / 实色按钮底 | `#49667C` | `#232323` | `#E9E9E9` |
| 实色按钮文字 | `#FFFFFF` | `#FFFFFF` | `#161616` |

候选值尽量沿用现有基础色，雾蓝操作色起点略加深。概念稿须复核实际叠层后的普通文字 4.5:1、大字和关键非文字边界 3:1，包括已选、禁用、按压与警告在真实表面上的区分。分隔线可弱化，前提是不会用它单独表达可操作性。映射至现有 `LithicTheme` / `LithicVisuals`，保留三套固定主题。[现有颜色角色](../../../app/src/main/java/com/cooper/lithic/core/design/LithicVisuals.kt)

## 3. 字体层级

先沿用 Android 系统无衬线与中文回退字体。每屏用一个明确阅读焦点。首页以适中的金额组起笔，项目/订阅详情以名称起笔，分析先给选定日期及指标，表单先给任务标题和首个字段。

| 角色 | 候选字号 / 行高 | 使用 |
| --- | --- | --- |
| 主读数 | 32 / 40sp，Medium | 首页总成本、趋势选中主读数 |
| 页标题 / 记录名称 | 24 / 32sp，Medium | 顶级页、详情 |
| 分组标题 | 18 / 26sp，Medium | 档案分组、时间线、表单分组 |
| 条目名、字段、主操作 | 16 / 24sp | 物品与订阅名称、常规输入 |
| 次要事实、状态、行内金额 | 14 / 20sp | 类别、时间、状态与口径，金额根据角色保留清晰字重 |
| 图表刻度、短单位注记 | 12 / 16sp | 仅用于短标签，关键数据另有完整读数 |

成本通过现有 `MoneyMetric` 统一呈现。完整保留人民币符号、单位、真实零值、负值、未知占位以及完整金额查看/复制。窄屏或大字先重排行列，保留现有超长金额兜底。多个同口径项目可用分组标识配合简洁行级金额，辅助技术仍能逐条读到指标名称。订阅行需明确「历史平均日成本」。[金额实现](../../../app/src/main/java/com/cooper/lithic/core/design/MoneyMetric.kt)

## 4. 间距体系

采用 4dp 子步进，常用 8、12、16、24、32dp。紧凑宽度页边距 16dp，较宽窗口从 24dp 起；同一条档案的事实间距 4–8dp，照片与文字 12dp，连续条目优先用 12–16dp 内间距与细分隔，独立段落 24–32dp。操作目标至少 48×48dp，视觉图标保留较小尺寸。先验证常用窗口与系统字体，再决定内容最大宽度和宽窗分栏，保留阅读行长。

## 5. 图标规范

沿用黑石品牌标识和当前语义明确的图标资源。搜索、返回、信息、更多、新增与导航用一致的线条重量和 20–24dp 光学尺寸，实际命中区另计。普通设置项以标题和分组支持扫读，只有能加快识别的动作使用图标。类型图标用于无封面占位；类别文字仍可读。纯装饰图标从朗读树排除，独立按钮提供具体名称，如「查看全部长期项目」。

## 6. 圆角与表面层级

档案和历史列表首选连续画布、留白与细分隔。照片框、控件和浮层依其职责各自使用圆角，照片可从 8–10dp、普通控件 12dp、浮层 20–24dp 起比较。保持三个表面层次：内容画布、需要区分的任务表面、模态层。只有确实需要触屏反馈或悬浮层次时用轻阴影。以当前位置、选中状态和操作重要性决定何时填色。

## 7. 图片与封面规范

首页以现有常用 80×60dp（受限宽度缩至 64×48dp）、4:3、`ContentScale.Fit` 为对照基线，保持横竖图内容完整。用档案条目对齐解决无图落位，统一有图与无图的文字起线、名称及金额层级。列表保持小缩略图并审查当前 Crop 的可辨认度；详情提供更大的阅读空间，沿用现有已授权的封面读取、查看和编辑范围。无图显示现有类型图标，已有引用但读取失败保留「封面暂不可用」及原反馈。无图、真实图和读取失败各自纳入审查。概念阶段使用合成图片或有使用许可的物品照片。生产只显示该记录自己的合法封面。[封面组件](../../../app/src/main/java/com/cooper/lithic/feature/media/CoverPreviews.kt)

## 8. 页面布局原则

| 页面家族 | 阅读顺序 | 表达 |
| --- | --- | --- |
| 现在 | 品牌/搜索 → 当前成本、截止日与口径 → 两类档案 → 含历史数量及成本构成 | 降低通栏色块的视觉重量，保留每类最多两条及现有排序。照片和名称形成连续浏览入口 |
| 当前列表、历史、搜索 | 任务标题 → 搜索或现有筛选 → 真实结果 | 连续清单。历史与当前由分组和文字标识。显示加载、分页和旧结果时效 |
| 两类详情 | 名称、封面、状态 → 对应成本 → 关键事实 → 时间线 | 物品优先持有和资金事实；订阅区分当前套餐、历史平均日成本、真实付款和折算付费时长 |
| 表单与状态操作 | 任务名 → 必填事实 → 影响预览/约束 → 保存或确认 | 字段和后果优先，主要操作固定可达 |
| 回看与分析 | 所选范围/指标 → 可读图形 → 可核对事实/解释 | 保留真实空白与错误反馈，按任务组织现有入口 |
| 设置与数据 | 任务分组 → 操作或当前值 → 需要就地解释的风险 | 轻量设置列表。完整备份、检查与覆盖恢复各自呈现目的及阶段 |

首页同时对照正常、有图、无图、封面不可用、仅历史、确认空账本、真实零值、读取失败且有旧快照及无快照。最后一种沿用受控首页场景，无法取得成本显示「—」，数量未知，省略无数据支持的日期及「非今日扣款」。其余日期或口径只随可信快照展示，旧值明确标注。保持真实 StorageGate 和预览分路重试。[首页状态呈现](../../../app/src/main/java/com/cooper/lithic/feature/home/HomeOverviewPresentation.kt)

## 9. 导航规范

紧凑宽度保留「现在／回看／设置」三个 Material 目的地及选中语义。仅在宽窗设计获得验收后评估同样三个目的地的侧栏呈现。二级页面显示上下文标题和返回；从搜索、历史、首页和分析进入的详情继续回到真实来源。一个首页新增入口，普通字号可以对照圆形 FAB 与有空间的独立操作区，关键是所有滚动位置的正文与焦点均可见。保留 200% 系统字号下已验证的非覆盖布局原则。系统手势、工具栏返回、切 Tab、预测返回及所有导航守卫走现有 Nav3 决策。[导航和守卫](../../../app/src/main/java/com/cooper/lithic/app/LithicNavigation.kt)

转场以即时切换或短促的单层变化为默认候选。系统关闭动画时可静态完成。同一方向不同时展示两层可读文字；返回预览要尊重原页面和未保存保护。无端侧证据前，对流畅度只记验证目标。

## 10. 表单规范

使用原生输入和日期选择；分组按操作而定。首次录入优先名称、日期、金额；必要的关联选择和受支持的可选项可展开。续费同时标明付款日期与生效周期；金额和类别的校验反馈落在字段附近，必要时滚动到错误位置。提交区实占布局高度并响应 IME，错误、提交中、明确成功、未知各有独立反馈。保留原始输入、解析、提交票据、重复提交保护、待确认结果和系统返回合同。读取失败与写入结果未知分别说明，提交结果未知保留安全离开与核查机制。[表单容器](../../../app/src/main/java/com/cooper/lithic/core/design/C2Page.kt)

## 11. 弹窗规范

新增类型选择沿用原生 BottomSheet。普通口径和说明使用信息入口，金额完整值支持现有选择与复制。需要中断并确认时使用 Material Dialog 或现有独立确认页，标题讲清动作，正文说明具体对象、结果、影响及可取消方式。项目删除、订阅及付款删除、交易组相关影响、丢弃输入、覆盖恢复保留各自真实后果与原守卫。区分结束、停止、取消计划停止、永久删除记录和取消显示封面。覆盖恢复提交中和结果未知保留独立、安全的状态界面。

## 12. 图表规范

默认读序为日期/期间、准确值、曲线、贡献、完整点和事件。用线型、文字标签及选择标记协助区分序列。零线、负值、缺失区段和待核对旧图各自可辨。保留精确选日、前后日、列表替代、事件日期和原记录跳转，轴域与技术口径仍可查。年度展示保持项目实际投入/收回与订阅实际付款分开。已有可访问的准确文本路径继续独立于拖动图表使用。[图表和选日](../../../app/src/main/java/com/cooper/lithic/core/design/CostChart.kt)

## 13. 无障碍规范

触控目标至少 48dp，复合点击区避免重叠。TalkBack 每条档案按名称、事实、完整金额与单位阅读，独立操作可聚焦、有明确角色。标题使用标题语义，状态不靠颜色，错误可定位且不会把焦点送到隐藏层。核对 320/360/400dp、宽窗口、横屏、正常与系统 200% 字体、长中文、极端金额及空状态。验证手势/三键导航、状态栏与刘海安全区、IME、系统返回与关闭动画。自动语义检查验证结构，端侧 TalkBack 验证实际朗读及焦点。各证据单独登记。

## 14. 三套主题的设计原则

- **岩白雾蓝**采用暖白画布，雾蓝集中在选中状态、信息链接与少量交互区域。封面保持真实颜色，首页成本区用字重与短分隔建立层级。
- **纯白**采用中性白，靠清晰黑灰文字、间距和细线组织内容；同页尽量维持连续阅读。只有输入、浮层或选中项需要轻灰表面。
- **深色黑灰**采用炭黑画布，使用略亮表面区分交互层与浮层，减少描边，防止暗照片与背景边界消失。主读数和正文有清楚明度，图表序列可独立辨认。

三个主题的入口、阅读顺序、状态和语义一致。后续审查用同组照片、同套记录与三个不同状态进行对照，确认差异来自表面与强调角色。主题选择与持久化沿用现有行为。

本轮只建立方向和可审查标准。实施顺序及每阶段验证见[重设计计划](V3_REDESIGN_PLAN.md)。
