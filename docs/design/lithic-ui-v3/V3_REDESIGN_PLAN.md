## 设计复核的重点

- 首屏继续给出成本与日期，但由物品身份承担浏览重心。先用同一组真实比例物品照片验证三主题和密度，再判断蓝灰页首应减弱到何种程度。
- 三主题须用同一组页面和状态验证文字、分隔、选中、警告、焦点与图表。纯白与雾蓝靠各自的表面和强调规则形成差异。
- 普通字号新增控件的覆盖风险来源于历史 A2 截图及共享布局结构。后续在正式生产 UI 路径复现，再决定操作落位。系统 200% 的既有修复是回归基线。
- 订阅缺少通用资料编辑目的地。概念只呈现已有的付款纠错、续费和状态任务。自动提醒、严格 JPEG 和历史照片永久删除按既有产品边界处理。
- 保持 Room、备份格式、金额算法、Repository、Owner/恢复、媒体协议、主题持久化、正式包名、签名和版本。若后续设计需要改变这些合同，停止受影响批次，单列差异供确认。
