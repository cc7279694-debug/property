# 订阅详情设计

`DESIGN_REVIEW_ONLY — NOT_PRODUCTION_UI`

打开详情先认出服务，再看到它长期平均每天花多少、此刻适用哪个套餐、每笔钱何时付。订阅采用紧凑身份区，为套餐和付款日期留出首屏空间。项目用照片识别物品，订阅用名称、类别和状态识别服务。

## 页面阅读顺序

| 区域 | 纯白基准稿 | 事实来源与操作 |
| --- | --- | --- |
| 顶栏 | 返回、订阅详情、更多 | 返回语义沿用当前来源，更多打开既有订阅管理面板。 |
| 服务身份 | 小型订阅标识或已有封面、名称、类别、状态 | 使用已登记封面。无封面用通用订阅图标，已关联但不可用与读取中分别呈现。状态使用「订阅中」「已到期」「已暂停」「已停止」。 |
| 主金额 | 历史平均日成本、结果截至日期、说明入口 | 读取 `historicalAverage` 和 `asOf`。说明内保留月 30 天、季 90 天、年 365 天的折算规则。折算付费时长和实际已过去的付费有效天数分别呈现。 |
| 当前套餐 | 价格、周期、当前标准日均价、生效日期、付费到期边界 | 仅当前有效套餐显示价格及当前标准日均价。到期边界明确标注「当天不包含」。已确认的未来周期保留「已付下一期尚未生效」，对应付款事实留在付款历史。 |
| 付款和状态事实 | 累计已确认实际付款、真实付款历史、状态事实及原备注 | 金额取 `confirmedPaidCents`，历史使用原分页。状态行保留生效日、原因、备注和「修正这条状态事实」。无备注时省去空标签。 |
| 底部动作 | 「记录真实续费」占独立底部区域 | 仅按现有逻辑在非已停止状态展示，读取中或详情读错时禁用。已停止的「重新开通」仍从管理面板进入。 |

## 样本与时间口径

同一笔付款的「真实付款」与「生效／到期」各占一行。付款先按 `paidOn` 降序，同日按稳定 `id` 升序。未来期即使在历史首行，也只因实际付款日期较晚。点击「付款及覆盖日期」可查看提醒到期日等现有事实。行内更多保留「修正这笔付款」「删除错误付款」。列表继续使用每页最多 50 条及显式「继续读取付款历史」。

| 合成阅读服务 · 内容 · 订阅中 · 观察日 2026-11-13 | 真实付款 | 覆盖 `[生效, 到期)` | 画板结果 |
| --- | --- | --- | --- |
| 下一期（月付） | 11-10，¥89.40 | 11-26 至 12-26 | 尚未生效，已纳入累计与历史平均 |
| 当前期（月付） | 10-26，¥59.40 | 10-26 至 11-26 | 当前标准日均价 ¥1.98/天 |
| 合计 | ¥148.80 | 60 个折算付费日，19 个实际已过去的付费有效日 | 历史平均日成本 ¥2.48/天 |

套餐事实按当前覆盖和状态呈现。已暂停、已停止或已到期时，显示「当前无有效套餐」，真实的 `¥0.00/天` 标为「当前日均贡献」。历史均值按已经确认付款的标准日计算，继续显示其原有数值。价格历史仍是按选定日期查看标准日均价或当前贡献的独立页面，保留原图表入口、精确选日与说明。

## 状态与管理

- **读取失败**。详情有旧值则标注「以下为上次读取记录」，保留原金额和日期及「重新读取」。没有可信详情时显示错误及重读，保持未知值语义。成功确认找不到记录使用现有「订阅不存在」状态。
- **付款历史单独失败**。已有付款行保留并标注上次读取，付款纠错不可用。只有确认为空的模型条件才出现「暂无付费记录」。现有仓储会拒绝没有真实付款的已存订阅，此状态画板为模型分支对照。
- **已暂停、已停止与计划停止**。暂停且覆盖已到期时保留原核对提示。已停止使用管理面板「重新开通」。有未来停止计划时显示固定生效日期，以及「修正停止计划」「取消尚未生效的停止计划」。付款纠错保持原固定停止日期。
- **暂停和停止确认**。管理面板保留原文「暂停、恢复或停止只改变砺石中的记录；取消服务商自动续费需到服务商处操作。」确认页保留真实付款历史、停止方式和固定边界提示。支持现有「到期后停止」「提前停止」，沿用适用条件与日期校验。恢复与重新开通进入现有核对或实际付款表单。
- **付款纠错、删除与返回**。纠错保留原笔身份。删除错误付款确认保留真实付款日期、金额、只删除这一笔及重算后果，最后一笔保持保护。返回走原放弃输入与未确认提交守卫，结果不明时继续核对同一提交。

入口包括现在、订阅列表、回看、已停止订阅、长期复盘、趋势、类别和年度回顾，也保留现有搜索及里程碑来源链。状态页、续费页与价格历史使用现有路由。详情中没有编辑服务身份或订阅照片写入入口。样稿的服务标识取通用图标；管理能力以本地事实为限。
