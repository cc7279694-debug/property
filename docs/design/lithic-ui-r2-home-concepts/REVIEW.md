# 砺石 LITHIC 首页概念探索 R2

**LITHIC-UI-R2-HOME-CONCEPTS**

本轮用三个首页阅读顺序探索 A + C，以清晰排版和克制的界面承载私人长期记录。沿用砺石黑石图标、三套主题、现有首页功能和业务口径。设计比较基线为 [R1 首页方案](../lithic-ui-r1/REVIEW.md)（`7bad974203d8e087b1c35418db863eb8aa5c5484`），对应生产 App 树 `39295c800ceefdeee19aefce39b26755d3b8d63a`。本轮使用独立设计分支 `codex/lithic-ui-r2-home-concepts`。

## 三个方向

| 方向 | 阅读顺序与气质 | 相对 R1 的结构变化 | 优点与取舍 |
| --- | --- | --- | --- |
| **01 Quiet Ledger 静默账本** · 先读清一个数字，再浏览记录。 | 当前日均成本直接排在页面上，日期和非今日扣款紧随其后。数量读作一条档案摘要。项目与订阅用自然行、缩略图和细分隔承接。对齐和字重建立秩序，物品身份让记录有归属。 | 移去成本主卡和两张数量卡，页面沿一条阅读线展开。留白用于分隔信息，不依靠图标色块标记每个区块。 | 成本最快可辨，适合高频核对。首屏对拥有物本身的表现更轻；需验证金额很长或字体放大时，主数字仍完整。 |
| **02 Personal Archive 私人物档** · 从一件长期拥有的物品进入首页。 | 先呈现带封面的项目条目，名称、持有状态与日均跟在图片下。全账本成本另置为横向注记，与单件物品金额有清楚标签。订阅沿档案条目的文字秩序呈现，已录入数作为末尾分类索引。 | 物品照片取得首要视线，成本仍在首屏。保留一个真正的内容焦点，避免把每个数据项做成独立组件。 | 最能传达私人物品档案感。缺封面、大字体或第二条记录出现时，需检验首屏成本的可见性与下方入口的可达性。 |
| **03 Daily Companion 日常陪伴** · 开屏先看成本，随即扫到手边的物品和订阅。 | 顶部用紧凑成本带承接主金额与成本构成入口，下接同一行的两类登记量。项目与订阅合入一个分段内容面，类型、名称、状态与各自成本可顺序扫读。 | 将 R1 的主卡、独立数量卡和分开的预览节奏改为成本带、成组数字、连续记录三个层次。 | 成本和物品均保持前置，使用频率高时易扫读。共享内容面要验证两类记录的分隔，避免订阅历史日均被误读为项目当前日均。 |

**推荐 02 私人物档。** 打开首页先能认出自己的物品，成本和日期仍在同一屏。这个顺序最贴近用户希望砺石成为私人物品档案的方向。下一阶段应先用无封面、两条项目预览和系统大字核对首屏。无封面时把首条收成带类型图标的普通行，第二条沿现有顺序接续，不为缺图留大空框。若更看重每天最快扫完两类记录，03 是更合适的选择。

## 三套主题

| 方向 | 岩白雾蓝 | 纯白 | 深色黑灰 |
| --- | --- | --- | --- |
| 01 | 岩白页面承载开敞数字，雾蓝用于操作和轻标记。 | 白底、墨色数字和细灰分隔。 | 炭黑页面与明亮数字建立优先级，记录行靠分隔和留白组织。 |
| 02 | 暖底衬托布面与阅读器，雾蓝留给链接与操作。 | 白底衬托原色照片，档案标题与注记以中性色组织。 | 封面保持原色，暗底与文字块分出照片、项目事实和成本注记。 |
| 03 | 暖白背景、雾蓝成本带，记录合面维持清晰层次。 | 白底与中性浅灰成本带、记录分隔。 | 深底、较亮的成本带与记录面分工，保留白色主金额及可辨辅助字。 |

## 同一组数据和入口

九个视图使用同一组合成示例。基于 [C2VisualFixtures.kt](../../../app/src/androidTest/java/com/cooper/lithic/ui/C2VisualFixtures.kt)，截至 2026-10-26 的当前日均成本为 **¥10.52/天**，并标记「非今日扣款」。项目为合成阅读器，持有 121 天，当前日均 ¥9.92/天。订阅为合成阅读服务，折算付费 30 天，历史平均日成本 ¥0.60/天。长期项目和订阅各 1 条，登记总数注明「含历史」。

各案共用一张 [生成式合成封面](mockups/reader-cover.jpg)，尺寸和裁切随布局变化。素材由 ImageGen 生成，导出为 900 × 600 的画板资源，仅用于表现用户已有封面时的样子。订阅图标、交互图标和黑石标识沿用现有资源。

搜索留在顶部。右下新增仍为现有入口。两组「全部」分别进入现有项目或订阅范围，条目仍指向对应详情。「成本与类别构成」及口径说明保留。底部三个目的地保持「现在 / 回看 / 设置」。交互边界依据 [HomeShell.kt](../../../app/src/main/java/com/cooper/lithic/feature/home/HomeShell.kt)。

空账本以「—」表示金额并提供简短引导，已知 0 显示真实金额。只有历史时保留含历史数量，并说明当前暂无有效记录。未取得或读取失败时区分未知和保留旧结果，沿当前逻辑显示日期、提示与重试。01 的提示跟随主数字，02 放在成本注记并为无封面留出非图片条目，03 放在成本带或对应记录分段。画板展示有记录的常态。

使用本机 Chrome 157 离线渲染三张 1240 × 1024 px 画板并逐张查看。360px 和额外的 320px 浏览器视图均核对了九个首页，样本无内容溢出，按钮最小边 48 CSS px，黑石标识与合成封面均正常载入，三个成本值及各入口都存在。画板的正文、辅助文字和操作色在各自主题平面上的最小静态对比分别为 6.07:1、6.66:1、7.87:1。源文件默认展示全部九个视图，使用 `?board=quiet`、`?board=archive` 或 `?board=daily` 可单独查看。

**Android 真机待验**：系统大字及窄屏时的金额、照片与区块重排；TalkBack 顺序、两个「全部」的准确名称及 48dp 实际命中；滚动与底部导航、搜索与键盘、系统返回、三主题实机对比。画板不作为 Android 运行或无障碍证据。

本轮差异仅在 `docs/design/lithic-ui-r2-home-concepts/`，包含三张画板、报告、概念 HTML 和合成封面。生产源码、资源和测试沿用上述基线。等待用户与 ChatGPT 选择方向。
