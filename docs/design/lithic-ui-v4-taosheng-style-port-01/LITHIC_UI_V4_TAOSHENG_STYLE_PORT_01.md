## 3. 全局视觉规则

| 角色 | 设计候选 |
| --- | --- |
| 间距与适配 | 4、8、12、16、20、24dp。标准页面左右 16dp，主区段距 20dp，同级卡片间距 12dp。宽窗口限制内容宽度并居中。截图采用手机逻辑宽度，实际布局以文本测量和系统安全区重排。 |
| 字体 | 使用系统中文字体。常用层级参考大标题 32/38sp、页面标题 20/26sp、区内标题 16/22sp、正文 15/21sp、次级 13/18sp、小字 12/16sp。画板品牌 25sp、详情名称 23sp、主要金额 26sp，首页主日均 32sp。日期及单位弱于金额。金额用 `MoneyMetric` 及现有元、日均语义，完整金额、币种和小数精度沿用原组件。 |
| 表面 | 普通卡约 18dp、概览 24–26dp、底栏和主按钮全圆角。用细描边或相邻分区的一条细分隔线组织内容。轻主题的浮层可用软阴影，深色靠明度与细边区分。记录组内不重复画卡框。 |
| 分段和状态 | 项目与订阅放在一条底轨，选中独立填底。类别、时间和常规状态先用文字，只有需要快速辨识的重要状态使用小胶囊，同时保留清晰文本。 |
| 操作与图标 | 主操作使用一枚实色胶囊，触控高度至少 48dp，可以随大字增高。次操作用文字或窄边按钮并保留同等可点面积。搜索、新增、返回、更多使用砺石自己的图形，装饰图形不重复朗读。 |
| 表单、Sheet、Dialog | 容器和字段用主题表面与填底角色区分。表单沿用字段标签、错误提示及焦点次序，随 IME 显示正确滚动。Sheet 顶部圆角和统一留白，确认框保留真实操作名称、后果、取消及资格限制。 |
| 可访问性 | 标签适配真实字号。检查 320、360、400dp、200% 系统字体、长名称、长金额、TalkBack 选中状态、键盘和手势/三键模式。重要状态同时用文字或形状表达。 |

## 4. 底栏

三个入口依次为「现在」「回看」「设置」。候选为宽约 234dp 的居中胶囊，内垫 5dp，默认单项高不低于 48dp，底边位于系统导航安全区上方 14dp。大字时外壳可加高和适当增宽，纯文字标签完整显示。选中项的圆角填底和文字同时更新，栏面采用近实色填底配细边，白色/雾蓝用极轻阴影，深色抬亮一层。

TaoSheng 的实时背景模糊半径为 22dp，底栏字号上限为正常字号的 1.15 倍。砺石候选以近实色底板模拟层次，通过可变胶囊尺寸容纳大字体。点击回调用现有导航，页签采用选中语义，触控范围保留 48dp。切页约 200ms 淡入淡出为候选参数，选中底色轻微过渡，系统关闭动效时可立即更新。内容按胶囊实际高度和系统安全区留出位置，和首页「添加」各占独立空间。输入法出现时胶囊让位，保持 Android Back、IME 及表单守卫测试。

## 5. 首页

保留品牌与现有搜索、顶部加号。概览并置「总投入」与「日均成本」，保留当前日均成本的无障碍名称，以及统计日期、含历史的两类数量和「成本构成」。金额口径入口维持可达。总投入只累计截至观察日的长期项目投入，日均成本沿用原计算，缺少可信快照时继续显示未知，真实零与确认空账本各有独立呈现。读取失败、上次结果和未确认状态沿用原提示，项目和订阅预览保留各自已有的重试入口。

紧凑分段条右侧保留「全部」，使用所选类别的现有列表回调。项目或订阅从现有预览取最多两条同批次记录。每条一张卡，显示 4:3 封面、名称、简短元数据和金额。首页预览沿用当前 `Crop`，无图与读图失效仍可区分。项目日均与订阅历史平均的语义分开；底部「添加」与顶部加号打开同一菜单，其下为独立主导航。

## 6. 两种详情

- **项目**保留返回、更多、已有封面及只读查看、紧凑身份、日均成本与累计投入两个同级值。封面保持 `Fit`，无图、不可用及已存在的照片操作沿用各自资格。财务明细默认收起，展开后显示现有投入、收回、净投入和非现金折抵信息。金额记录默认显示按现有顺序选取的三笔，超过三笔才可展开，单笔详情、原纠错与结算约束保留。「更多资料」和固定「记一笔」沿用原路径。大字时同级金额可纵排。
- **订阅**保留服务名称、类别、状态，以及已登记封面或合适的通用占位。核心是「历史平均日成本」。当前套餐与已经付款但尚未生效的下一期分开；没有下一期时该行消失，没有有效套餐保留现有状态。付款按真实日期，默认三笔，「全部」展开已加载条目，分页仍由现有入口读取。保留单笔、更多资料、暂停/恢复/停止等管理资格，符合条件时显示固定「记录续费」。

详情视觉金额沿用已冻结简写。读屏继续提供完整金额和日均单位。视觉措辞或排序以现有源模型和原回调为准。

## 8. 生产文件范围建议

- `app/LithicNavigation.kt` 的 `C2PrimaryNavigationBar` 及底边空间协调。保留原路由、页签状态、标签与回调。
- `core/design/LithicTheme.kt`、`LithicVisuals.kt`、`LithicControls.kt` 分别承接颜色、间距、字号和表面等展示角色。先检查调用范围，避免改变其他页面的默认表现。
- `feature/home/HomeShell.kt` 调整品牌区、概览、分段、记录卡和添加区的展示。复用 `MoneyMetric.kt`、`C5Information.kt`、`CoverPreviews.kt` 的现有接线。
- `feature/project/ProjectDetailScreen.kt` 和 `feature/subscription/SubscriptionDetailScreen.kt` 仅调整展示层、触控区域和主题应用。相关 AndroidTest 按现有 TestTag、动作与安全断言补视觉证据。
- 表单及通用 Sheet 或 Dialog 在确有共用样式需求时再评估 `FormFields.kt`、`C2Page.kt` 及各调用方。文件范围以独立评审后的实施授权为准。

## 9. 冻结边界

Room、迁移、backup4、Repository、Owner、generation、恢复 Token 和财务计算口径均为既有合同。Nav3 的路由、返回来源、表单未保存守卫、未确认写入、原子恢复与危险操作确认按当前生产链路。照片沿用安全读取、Owner、请求票据、预算及导入引用合同。主题持久化、正式应用身份、签名、版本和历史 APK 属于发行边界。

## 10. 评审后实施顺序

1. **底栏与局部主题角色。** 冻结外壳、页签比例和真实选中态，再做三主题、系统边栏区、大字体、Back/IME 和守卫对照。
2. **首页。** 同一组数据和相同视觉角色复核尺寸、空状态、旧快照、真实零、长金额、两种预览和新增入口。
3. **详情。** 项目、订阅分别核对价格含义、照片、记录分页/折叠、纠错与写入保护，再对比画板的卡片、列表和主按钮。
4. **共用组件。** 按实际调用者推进其余页面、表单、弹层，做视觉与行为回归。每批提交实际 Android 截图与画板并排对照。

本提交用于设计核对。浏览器证据见[视觉验证记录](VISUAL_REVIEW.md)，Android 视觉、系统字体、TalkBack 和导航运行结果为 `NOT_RUN`。生产实施等待 ChatGPT 独立评审。
